# Исправление остановки и запуска сервисов

Проверка 31 октября 2026 года выявила причину задержек: после запуска прежних `stop_all.bat` и `start_all.bat` на порту 8000 оставался процесс PID 90060 с API версии 0.2.0. Новые обработчики сравнения подхватывали исходники 0.2.1, поэтому версия в отчёте отличалась от версии долгоживущего API. Постоянный конвертер в этом API не запускался. Последний такой прогон: подготовка первой версии 21,886 с, обеих — 44,867 с.

Остановка раньше опиралась только на PID-файлы и точное совпадение пути интерпретатора. Это пропускало ручной запуск и могло не распознать базовый Python за виртуальным окружением. Запуск проверял имя сервиса и каталог установки, но принимал устаревшую версию за готовую.

## Изменения

- Общие функции управления процессами вынесены в `scripts/service_processes.ps1`.
- Остановка находит слушателей настроенных портов и процессы из PID-файлов. Проверяются путь Python внутри `runtime` этой копии проекта, точный модуль Uvicorn и порт. Чужие процессы не останавливаются.
- PID повторно проверяется перед остановкой. После неё проверяется освобождение порта; только затем удаляется запись процесса и выводится сообщение об успехе.
- Проверка запуска сверяет версию с `config/release.json`. Для сервера сравнения требуется включённый постоянный конвертер; перед объявлением готовности ожидается прогрев.
- Пути интерпретатора из виртуального окружения и его базового процесса могут различаться: принадлежность проверяется по фактическому процессу, модулю и папке установки.

## Проверки

PowerShell-сценарий `tests/service_lifecycle.ps1`, запускаемый через pytest, проверяет отсутствие PID-файла, различие пути venv и базового Python, чужой процесс, устаревший PID, смену процесса после обнаружения, устаревшую версию API и отсутствие ускоренного конвертера. В этих проверках системные вызовы заменены фиктивными и реальные процессы не завершаются.

Дополнительно создан реальный временный веб-сервис на порту 18080 без PID-файла. Новый механизм распознал и остановил только его, проверил освобождение порта; основной сервер остался доступен. Затем исправленными скриптами остановлены три подтверждённых сервиса проекта и начат штатный общий запуск.

Команда регрессии: `runtime/dev/Scripts/python.exe -m pytest tests/test_service_launchers.py -q`.

## Результат штатного перезапуска

Все три сервиса остановлены и запущены исправленным bootstrap. API версии 0.2.1, постоянный конвертер включён и готов. На той же паре old_generated.docx / new_generated_v2.docx: первый список изменений получен клиентом за 2,876 с, первая PDF-версия — за 8,041 с, вторая — за 10,884 с. Время внутри worker: 5,242 с и 8,225 с. До исправления пользователь наблюдал 22 и 44 с. Полная обработка с холодной загрузкой моделей заняла 56,107 с; страницы доступны раньше классификации. Найдены 24 изменения, ИИ использован, предупреждений нет.

В проверочном скрипте устранена гонка: завершение задачи между чтением предварительного снимка и запросом отчёта теперь допускается и подтверждается состоянием completed.
