# Исправление сравнения Word–PDF, 01.11.2026

Проверены old_generated.docx, Договор_исходный.pdf, JSON-отчёт и Word-отчёт пользователя. Word-отчёт содержит таблицу из 50 строк: заголовок и 49 записей. JSON содержит 40 вставок, 6 удалений, 2 удаления строк и 1 изменение подписи.

## Причины

- Word хранит логические абзацы, PDF — расположенные на страницах символы. PDF-переносы и разрыв пункта 2.4 между страницами мешали сопоставлению.
- Колонтитулы PDF попадали в основной текст, повторялись на каждой странице и содержали вычисленный номер страницы. В Word это один колонтитул с полем PAGE.
- У таблицы реквизитов видимые границы были только у заголовка. PDF-экстрактор нашёл одну строку, остальное прочёл как чередующиеся строки двух колонок. Отсюда удаления строк Word и множество вставок реквизитов.
- Строгий разбор таблицы перекрёстных ссылок PDF завершался PdfStrictReadError. Ошибка разбора ошибочно попадала в список изменений как подпись. Реальной электронной подписи в этом PDF нет.

## Реализация

Добавлен comparison_server/cross_format.py. Для Word–PDF Word используется как источник границ логических блоков, а сравниваемые значения всегда берутся из PDF. Лексическое выравнивание распределяет весь поток PDF, включая несовпавшие вставки, по блокам. Проверяется сохранение всех токенов. Семантическая близость не используется как доказательство равенства.

Таблица с одним обрамлённым заголовком восстанавливается по физическим колонкам, только если заголовок и число колонок соответствуют Word и удалось определить конец области. После восстановления сравнивается мультимножество всех непробельных символов области: ни символ, ни дополнительная строка не должны исчезнуть. Неуверенные случаи сохраняют исходное извлечение. Заголовки/колонтитулы сравниваются отдельно; PAGE нормализуется только при подтверждённом поле Word и подходящем текстовом шаблоне. Неизвестный текст не отбрасывается.

PDF читается pyHanko в нестрогом режиме разбора структуры; криптографическая проверка подписи от этого не отключается. Ошибки инспекции остаются ограничениями, но не считаются доказательством изменения состава подписей.

## Проверка

На пользовательской паре: 0 различий в обоих направлениях. Через рабочий API также 0, подписи не обнаружены. Первое получение результата клиентом — 6,567 с; полный сценарий с сохранением отчётов — 12,808 с. Внутреннее время pipeline — 7,966 с. Для этого сравнения модели не нужны.

63 теста прошли. В набор входят контрольные реальные изменения суммы, процента, отрицания, email, ИНН и стороны; добавленный пункт PDF; сохранение токенов и координат; неизвестный текст колонтитула; ошибка инспекции подписи; существующие проверки diff, перемещений, API, очереди и подписей. Старая и новая структуры сравниваются без автоматического удаления пунктуации, цифр, кириллицы или латиницы.

Ограничения: произвольная структура PDF всё ещё не равнозначна структуре Word. Сложные многостраничные таблицы, сноски, нетипичные поля и неизвестная вёрстка могут требовать ручной проверки. OCR не добавлялся. Статус ограничений восстановления PDF не означает обнаруженное изменение и сохраняется отдельно от количества правок.
