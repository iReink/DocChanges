# Спецификация реализации Атлас 0.1

## Архитектура

Три независимых HTTP-процесса: веб-приложение (8080), сравнение (8000), модели (8001). Слушают адрес из конфигурации, по умолчанию 0.0.0.0. Все данные установки относительны корню проекта. Сервер сравнения использует отдельный дочерний процесс на задачу; отмена и тайм-аут завершают процесс и его дерево.

Состояния задачи: queued, running, completed, failed, cancelled. Статус выполнения, наличие изменений и полнота независимы. Хранилище задач в памяти; данные на диске временные, при запуске очищаются. Истории и списка задач нет.

## API сравнения

POST `/api/v1/comparisons`: multipart-поля `old`, `new`, `employee`, повторяемые `old_signatures`, `new_signatures`. Ответ 202: `id`, `state`. Файлы сохраняются под техническими именами; оригинальные имена остаются в метаданных. Ограничения: 50 МБ, 200 страниц, 10 подписей на сторону, 8 ожидающих задач, 900 секунд обработки, 1800 секунд простоя.

GET `/health`: service, version, ready. GET `/api/v1/capabilities`: форматы, ограничения, наличие конвертера и состояние моделей.

GET `/api/v1/comparisons/{id}`: состояние, этап, время создания, позиция очереди и ошибка. GET `.../result`: результат. GET `.../documents/{old|new}/preview`: PDF. GET `.../reports/{pdf|docx|json}`: отчёт. POST `.../heartbeat`: продление. DELETE задачи: отмена и очистка. Нет cookie-аутентификации. CORS разрешён для демонстрации.

## API моделей

POST `/api/v1/embeddings` и `/api/v1/entities` принимают `fragments: [{id, text}]`. Возвращают `model` с id/revision, устройство и `items`. Для эмбеддингов item содержит vector; для сущностей — entities с start/end, text, label, score. Индексы — кодовые точки Python. Исходные документы сервер моделей не получает.

GET `/api/v1/models/status`: скачанные модели, загруженная модель, текущее действие и устройство. HTTP-процесс доступен до загрузки весов в память. Исполнение сериализовано блокировкой. Ошибка модели возвращает 503; сравнение не теряет найденные кодом события.

## Извлечение

DOCX: XML основного текста, колонтитулов и сносок; абзацы, переносы, номера списков, строки/ячейки/объединения таблиц. Технические runs не являются изменениями. Исправления отклоняются с объяснением. DOC преобразуется локальным LibreOffice. Для Word создаётся PDF-представление. PDF: символы, координаты, геометрические блоки и таблицы. Изображения и страницы без текста отмечаются как ограничения, OCR отсутствует.

Блок содержит id, kind, text, paragraph, area, locations, rows, spans. Location: page, bbox `[x0, top, x1, bottom]` в PDF points, start/end, precision. Для Word связь со страницами строится по символам PDF-представления; неудачная привязка отражается в полноте навигации.

## Сопоставление и изменения

Лексическое сопоставление последовательностей с возможностью пропуска, вставки и объединения до трёх абзацев. Для неоднозначных фрагментов MiniLM предлагает соответствия. Близость векторов не отменяет точный diff. Одинаковые уникальные пропущенные блоки определяются как перемещение, дубликаты сохраняются консервативно.

Внутри соответствий — diff слов, знаков и пробелов с уточнением общего префикса/суффикса до символов. Замена — одно событие. Word–Word сравнивает явные переносы и границы абзацев. Для PDF переносы не являются доказательством изменения форматирования.

Таблицы: сопоставление таблицы, столбцов, строк, ячеек. Структурное событие вставки строки/столбца/таблицы учитывается один раз. В существующих ячейках правки самостоятельны. Изменения объединения — отдельные события.

Change: id, operation, categories, before/after, old/new_locations, old/new_paragraph, source, confidence, details. Operation и categories независимы: изменение суммы в ячейке не удваивает счётчик. Детали содержат диапазоны и контексты для NER, положения в таблице.

## Классификация и модели

Правила используют формат и контекст реквизитов, валюты, сумм, дат, организаций. Невалидный кандидат не удаляется из результата. GLiNER вызывается на изменённых контекстах; сущность принимается только при корректном диапазоне и пересечении с diff. Низкая уверенность оставляет обычное текстовое событие.

MiniLM: sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2. GLiNER: urchade/gliner_multi-v2.1. Точные ревизии — config/models.json. Длинные фрагменты разбиваются; эмбеддинги частей агрегируются. NER использует перекрывающиеся окна. На GPU одна модель, бюджет 2304 МБ; OOM уменьшает batch эмбеддингов и переводит выполнение на CPU. При недоступном ИИ результат получает предупреждения.

## Подписи

ASN.1-разбор CMS и извлечение сертификатов. Библиотека pyHanko проверяет подписанные атрибуты и математическую подпись над digest оригинала. RSA/ECDSA SHA-256/384/512. Неподдерживаемый алгоритм — not_checked. Присоединённое содержимое дополнительно сопоставляется с загруженным документом. Для PDF проверяются ByteRange, подписанная ревизия и последующие ревизии. Trust/revocation всегда not_checked; сетевые запросы к УЦ отсутствуют.

## Результат и отчёт

Результат хранит сведения о документах и хешах, сотрудника, время Asia/Yekaterinburg, count, changes, signatures, warnings, partial, coverage по областям, модели и версию алгоритма. PDF/DOCX/JSON строятся из одного результата. Оригинальные значения и страницы сохраняются в отчёте без зависимости от активного сервера.

## Запуск и диагностика

BAT → PowerShell bootstrap → локальный uv/Python → закреплённые зависимости → проверка ресурсов → Uvicorn. На новом пути/ПК среда пересоздаётся, модели повторно используются. PDF.js, шрифт и LibreOffice имеют проверяемые контрольные суммы. Серверное выполнение моделей offline/local_files_only. Общий запуск хранит PID и модуль для адресного завершения.

Проверки: tests, искусственные документы tests/fixtures, диагностический скрипт, TEST_REPORT. Требования промышленной аутентификации и защиты не входят в демо.
