# Вызовы API

Откройте `http://localhost:8000/docs` для интерактивной документации. Имена multipart-полей: `old`, `new`, `employee`, `old_signatures`, `new_signatures`.

С версии 0.3.1 веб-интерфейс по умолчанию вызывает те же методы через свой адрес с префиксом `/comparison-api`: например, `http://localhost:8080/comparison-api/api/v1/comparisons`. Это позволяет использовать один HTTPS-туннель на веб-сервер. `/health` веб-сервера сохраняет идентификатор `atlas-web`; `/comparison-api/health` возвращает health сервера сравнения. Прямой API на 8000 сохранён. Конечный адрес задаёт администратор через `api_url` в настройках веб-сервера; посетитель не может выбирать произвольный адрес назначения прокси. OpenAPI `/docs` остаётся доступен напрямую на сервере сравнения.

## Отправка из Windows

```bat
curl.exe -X POST http://localhost:8000/api/v1/comparisons -F "employee=Тестовый сотрудник" -F "old=@tests/fixtures/old.docx" -F "new=@tests/fixtures/new.docx"
```

Ответ: `202`, JSON с `id` и `state`. Сохраните ID для следующих запросов. При работе по сети замените localhost на адрес сервера.

```bat
curl.exe http://localhost:8000/api/v1/comparisons/ID
curl.exe http://localhost:8000/api/v1/comparisons/ID/result
curl.exe -o report.pdf http://localhost:8000/api/v1/comparisons/ID/reports/pdf
curl.exe -X POST http://localhost:8000/api/v1/comparisons/ID/heartbeat
curl.exe -X DELETE http://localhost:8000/api/v1/comparisons/ID
```

До первого текстового результата result возвращает 409. Затем результат доступен ещё во время обработки: `provisional: true`, `revision`, `checks`, `timings`. Состояние задачи содержит `result_available` и `result_revision`. Клиент опрашивает состояние и получает новую ревизию без перезагрузки страницы. После завершения `provisional: false`.

Каждая версия получает страницы независимо: `documents.old.pages` / `documents.new.pages` равны 0, пока просмотр ещё готовится. Endpoint preview возвращает 409 до готовности выбранной стороны. Публикация отчётов до завершения всей задачи запрещена (409). Финальный JSON сохраняет те же группы и их точные фрагменты.

Для удалённой или неизвестной задачи — 404. Превышение размера — 413, формата — 422, заполненная очередь — 429. Ошибки обработки документа находятся в состоянии задачи, поскольку проверка выполняется асинхронно.

## Сервер моделей

```json
{
  "fragments": [
    {"id": "clause-4", "text": "Общая стоимость составляет 500 000 рублей."}
  ]
}
```

Этот JSON отправляется POST на `/api/v1/embeddings` или `/api/v1/entities` сервера моделей. Порядок возвращаемых items соответствует входу; для связи используйте id. Индексы сущностей — Unicode-кодовые точки, end не включается. Ошибка модели — HTTP 503; веса во время запроса не скачиваются.

Одна запись changes — одна группа. Для отображения используйте `details.display_before/display_after`, если они присутствуют. Посимвольные операции и координаты находятся в `details.fragments`: `operation`, `before`, `after`, `old_range/new_range`, `old_locations/new_locations`. Не используйте родительские before/after как атомарные правки для реконструкции документа: они могут представлять целое поле или условие. Например, группа «3 % → 30 %» содержит точный фрагмент вставки одного нуля.

`partial` отражает ограничения анализа, `navigation_partial` — ограничения привязки к страницам. Предварительные значения явно отмечены полями checks. Предупреждение о координатах само по себе не понижает полноту чтения текста.

Координаты locations: страница с 1, bbox `[x0, top, x1, bottom]` в PDF points. Для Word используйте именно PDF preview этого задания. Порядковые номера блоков включают ячейки; это логический адрес, а не номер пункта договора.
# Изменения API в версии 0.2.1

Операция `row_move` обозначает одно перемещение строки таблицы: `details.old_row` и `details.new_row` нумеруются с единицы, доступны координаты обеих сторон. Операция `move` содержит `details.scope` (`block` или `sentence`). Для перенумерованного перемещённого пункта `details.renumbered=true`, исходные номера сохранены в `before`/`after`, посимвольная правка номера — в `details.fragments`. Дочерние фрагменты не увеличивают `count`. Клиенты должны допускать неизвестные операции будущих версий.

# Важно для интеграции: результат сравнения текста

`state: completed` означает завершение задачи, но не гарантирует, что текст удалось проверить. В `/result` проверяйте `comparison_status` и `checks.text`.

- `comparison_status: compared` — сравнение доступного содержимого выполнено; учитывайте предупреждения и полноту отдельных областей.
- `comparison_status: unavailable`, `checks.text: unavailable` — есть страницы без доступного текста, OCR выключен. `changes` пуст, а `count: 0` оставлен для совместимости структуры API. **Это не заключение «изменений нет».** Интерфейс и PDF/DOCX-отчёты показывают «Сравнение текста невозможно» и не формируют обычную таблицу правок.

У события `row_move` с `details.edited: true` есть `details.cell_changes`: вложенные правки значений. Родительская строка считается одним событием, вложенные детали не увеличивают общий счётчик.
