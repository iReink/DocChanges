# Полигон Xiaomi-OCR-0

Самостоятельный локальный модуль Атласа. Не изменяет существующие сервисы сравнения.

## Запуск на Windows

1. `setup_ocr.bat` — отдельный Python 3.13, зависимости, CUDA 13.0 и исходные веса модели (~1.75 ГБ). Первый запуск требует интернета. Загружаемые файлы и окружение остаются в каталоге проекта.
2. `start_ocr.bat` — запускает два скрытых процесса; откройте http://127.0.0.1:8020.
3. `stop_ocr.bat` — завершает только процессы этого полигона.

Проверенные версии зафиксированы в `requirements.lock` (Windows x64, Python 3.13, CUDA 13.0). Диапазоны зависимостей для разработки — в `requirements.txt`. PDF.js используется из существующего `vendor/pdfjs` проекта.

Модель загружается в память при первом распознавании. После установки обработка полностью локальная: `local_files_only=True`. На CPU работает существенно медленнее. Если GPU занят, завершите OCR-сервисы, задайте `$env:XIAOMI_DEVICE='cpu'` в PowerShell и выполните `./start_ocr.bat`. Доступны значения `auto` (по умолчанию), `cuda`, `cpu`.

## Модули

```text
Браузер :8020
   → ocr_lab.web — статика и HTTP-шлюз /api/*
      → ocr_lab.api :8021 — PDF, задания, результаты
         → ocr_lab.engine — Xiaomi-OCR-0 / Transformers / PyTorch
```

UI не импортирует модель. Для отдельной машины задайте веб-шлюзу `XIAOMI_API_URL=http://HOST:PORT`. Сервер модели по умолчанию слушает loopback; самостоятельный запуск: `runtime/envs/xiaomi-ocr/Scripts/python.exe -m uvicorn ocr_lab.api:app --host 127.0.0.1 --port 8021`. Для UI аналогично `ocr_lab.web:app --port 8020`. Внешний доступ и авторизация в этот локальный полигон не входят.

`XIAOMI_MODEL` позволяет указать другую локальную директорию весов. Репозиторий и неизменяемая ревизия записаны в `model.json`; повторная установка использует ту же ревизию. Скачать заново: `python -m ocr_lab.download_model` из выделенного окружения. HTTP-загрузка возобновляется по частям и проверяет LFS SHA-256.

## Интерфейс и измерения

- PDF слева, результат справа; перетаскивание, замена, просмотр оригинала.
- Markdown с преобразованием OTSL в HTML-таблицы; формулы сохраняются как LaTeX. Математический набор формул в просмотре не выполняется.
- Просмотр и исходный Markdown, копирование, экспорт `.md` и `.json` с исходными ответами модели.
- Прогресс по завершённым страницам, текущая страница, живой таймер и итоговое время. Процент отражает количество страниц, а не оценку оставшегося времени.
- Таймер задания включает загрузку модели и обработку. JSON содержит отдельное время первоначальной загрузки и время каждой страницы (растеризация + inference + декодирование). Время передачи файла не входит.
- DPI 96/144/192, длинная сторона до 2400 px, лимит 2048/4096/8192 токенов. При достижении лимита появляется предупреждение.
- Отмена проверяется при генерации токенов и между страницами; загрузка модели не прерывается. Готовые страницы сохраняются.

PDF всегда растеризуется: текстовый слой не извлекается, запасного OCR-движка нет. Используется режим whole-page с официальным промптом и детерминированной генерацией. Двухэтапный layout/region pipeline из бенчмарков модели здесь не реализован.

## API

Swagger: http://127.0.0.1:8021/docs

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Доступность сервера, модель загружена, устройство, занятость |
| POST | `/jobs` | Multipart `file`, `dpi=144`, `max_tokens=4096`; возвращает 202 и задание |
| GET | `/jobs/{id}` | Статус, прогресс, страницы, метрики, ошибка |
| POST | `/jobs/{id}/cancel` | Запрос отмены |
| GET | `/jobs/{id}/result?format=md` | Markdown; также json и очищенный html |

Статусы: queued → loading → running → completed / cancelled / failed. Один активный запрос; второй получает 409. Ограничения: 50 МБ, 100 страниц. UI работает через свой шлюз, поэтому отдельная настройка CORS не нужна.

В `temp/ocr-lab/{id}` остаются загруженный `input.pdf`, `result.md`, `result.json`. Они не удаляются автоматически; очищайте каталог вручную при остановленных заданиях. В памяти хранятся последние 20 заданий; после перезапуска результаты доступны в этих файлах, API-история не восстанавливается. В текущей вкладке активное задание восстанавливается при обновлении страницы, пока API продолжает работать. Логи: `logs/ocr-{api,web}.{out,err}.log`.

## Проверки

`runtime/envs/xiaomi-ocr/Scripts/python.exe -m pytest ocr_lab/test_api.py -q`

Проверяет контракт без загрузки модели: реальный image-only PDF, жизненный цикл, занятость, отмену, ошибки, сохранение и безопасный HTML. Настоящее распознавание требует установленных весов и отдельного запуска через интерфейс/API.

Результаты выполненного сквозного прогона на этой системе: [VALIDATION_RU.md](VALIDATION_RU.md).

Модель и промпт: https://huggingface.co/SeerRay-Lab/Xiaomi-OCR-0. Постобработка: https://github.com/xiaomi-research/Xiaomi-OCR-0 — см. THIRD_PARTY.md.

На Windows используются стандартные PyTorch-реализации recurrent/causal-convolution ядер. Оптимизированные `flash-linear-attention` и `causal-conv1d` не установлены; предупреждения об этом в логе ожидаемы. Полигон проверяет работоспособность этой конфигурации и не воспроизводит производительность SGLang/vLLM.
